# Правила документирования библиотеки `nexo`

## Общие принципы

1. **Язык комментариев**: Все документационные комментарии пишутся **на русском языке**. Английские комментарии допускаются только в кодовых примерах внутри ```` ```dart ```` блоков.

2. **Стиль dartdoc**: Используем стандартные документационные комментарии `///` (triple-slash). Начинаем каждую строку с `///`.

3. **Формат файлов**: Dart-файлы комментируем через `///`. Markdown-файлы — обычным текстом.

4. **Язык двойной документации**: Основные публичные API должны иметь и русскую, и английскую версию документации. Русская версия — основная (по умолчанию). Английская — в отдельных файлах `doc/` или в `@docImport`.

## Структура документационного комментария

### Классы и абстракции

```dart
/// Краткое описание назначения класса (1-2 предложения).
///
/// Дополнительные детали: где используется, паттерн, контекст применения.
///
/// ## Пример использования
///
/// ```dart
/// // Конкретный, рабочий пример кода
/// final example = ClassName(param: value);
/// final result = example.doSomething();
/// ```
///
/// См. также: [СвязанныйКласс], [СвязаннаяФункция].
class ClassName { ... }
```

### Методы и функции

```dart
/// Краткое описание действия метода (глагол в инфинитиве).
///
/// [paramName] — описание параметра (что принимает, формат, ограничения).
/// Если параметр обязательный — укажите. Если опциональный — уточните значение по умолчанию.
///
/// **Возвращает:** описание возвращаемого значения, его формат и возможные состояния.
///
/// **Бросает:** [ИсключениеТип] — при каких условиях.
///
/// ## Пример
///
/// ```dart
/// final data = await client.get('/api/users');
/// ```
///
/// Возвращает [Future], который завершается со [Right], содержащим список [User],
/// или [Left] с [NetworkFailure.noInternet] при отсутствии соединения.
Future<Result<List<User>>> fetchUsers() async { ... }
```

### Свойства (поля и геттеры)

```dart
/// Описание назначения свойства.
///
/// Значение по умолчанию: `значение`.
final String propertyName;
```

### Enum значения

```dart
/// Описание назначения enum-значения.
///
/// Используется когда: [условие/контекст].
enumValue,
```

### Миксины

```dart
/// Миксин, который добавляет возможность [что делает].
///
/// Используется совместно с [Класс] для [цель].
///
/// ## Методы
///
/// - [метод1] — описание.
/// - [метод2] — описание.
mixin MixinName on SomeClass { ... }
```

### Типы (typedef)

```dart
/// Тип функции для [назначение].
///
/// Принимает: [param] — описание.
/// Возвращает: описание результата.
typedef FunctionTypeName = ReturnType Function(ParamType param);
```

### Расширения (extensions)

```dart
/// Расширение [ИмяРасширения] добавляет методы [что делает] к [ТипКласса].
///
/// ## Пример
///
/// ```dart
/// final widget = Text('hello').pad(all: 8);
/// ```
extension ExtensionName on TargetType { ... }
```

## Правила для параметров

### Обязательные параметры
```dart

```dart

### Named параметры (bool flags)
```dart

### Callback-параметры
```dart

## Запрещённые паттерны

### ❌ Не делай так:
```dart
// Неправильно — нет описания параметров
/// Делает что-то.
void doSomething(String a, int b, bool c) {}

// Неправильно — нет описания возврата
/// Получает данные.
Future<Result<User>> fetchData() {}

// Неправильно — слишком общее описание
/// Метод для работы с данными.
void processData() {}
```

### ✅ Делай так:
```dart
// Правильно
/// Загружает данные пользователя по идентификатору.
///
/// [userId] — уникальный идентификатор пользователя (UUID v4).
/// [withCache] — если `true`, сначала проверяет локальный кэш.
///   По умолчанию: `true`.
///
/// **Возвращает:** [Future] с [Result<User>].
/// - [Right] — пользователь найден.
/// - [Left] — [NetworkFailure.noInternet] или [CacheFailure.notFound].
///
/// ## Пример
///
/// ```dart
/// final result = await useCase(userId: '123');
/// result.fold(
///   onFailure: (f) => showError(f.userMessage),
///   onSuccess: (user) => showProfile(user),
/// );
/// ```
Future<Result<User>> fetchUser({
  required String userId,
  bool withCache = true,
}) async { ... }
```

///

```

## Специальные блоки документации

### Блок "См. также"
Используй для ссылок на связанные API:
```dart
/// См. также: [ДругойКласс], [ДругаяФункция].
```

### Блок "Важно"
Для предупреждений и неочевидных вещей:
```dart
/// **Важно:** При использовании [метод] на платформе Web,
/// убедитесь что [параметр] установлен в `true`.
```

### Блок "Источник"
Для ссылок на документацию/спецификации:
```dart
/// Источник: [Firebase Auth Documentation](https://firebase.google.com/docs/auth).
```

## Многоязычная документация

### Стратегия

1. **Основной язык** — русский. Все комментарии по умолчанию на русском.
2. **Английская версия** — в markdown-файлах `doc/en/` или в `@docImport`.
3. **Примеры кода** — всегда на английском (имена переменных, классов).

### Пример двойной документации

```dart
/// Загружает список постов пользователя.
///
/// [userId] — идентификатор пользователя.
/// [page] — номер страницы (начиная с 1).
/// [pageSize] — количество элементов на странице (по умолчанию: 20).
///
/// **Возвращает:** [Future] с [Result<List<Post>>].
///
/// ---
///
/// Loads user posts.
///
/// [userId] — user identifier.
/// [page] — page number (starting from 1).
/// [pageSize] — items per page (default: 20).
///
/// **Returns:** [Future] with [Result<List<Post>>].
Future<Result<List<Post>>> fetchPosts({
  required String userId,
  int page = 1,
  int pageSize = 20,
}) async { ... }
```

## Чек-лист перед коммитом

- [ ] Все публичные классы задокументированы
- [ ] Все публичные методы задокументированы
- [ ] Все параметры описаны (`[paramName] — описание`)
- [ ] Возвращаемые значения описаны
- [ ] Указаны возможные ошибки (исключения / Failure-коды)
- [ ] Есть примеры использования для сложных API
- [ ] Нет дублирующей информации (не повторяем то, что очевидно из имени)
- [ ] Язык — русский (кроме примеров кода)
- [ ] Формат — `///` triple-slash
- [ ] Нет синтаксических ошибок в markdown-блоках
- [ ] Ссылки `[ClassName]` ведут на существующие классы
